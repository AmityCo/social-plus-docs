<Note>
  **Xcode forward compatibility restored in SDK 8.0.0**

  The Xcode 26 compatibility issue caused by **RealmSwift** binaries has been fully resolved in **SDK 8.0.0**. The cache layer has been migrated from Realm to **Core Data**, eliminating the Realm dependency entirely and restoring forward compatibility across Xcode versions. We recommend upgrading to 8.0.0 or later to remove any Xcode version constraints from your project.

  See the [iOS SDK v8 Migration Guide](/social-plus-sdk/changelogs/ios-sdk-v8-migration-guide) for full upgrade instructions.
</Note>

<Update label="8.12.0  (30/10/2026)" tags={["New Releases"]}>
  ## 🚀 New Features

  #### GIF Attachments on Posts

  Posts can now carry GIFs that your app picks from its own GIF provider. A GIF is a URL, not an uploaded file.

  - **Create or edit:** pass `AmityGifData(url:width:height:)` values to `AmityMixedMediaPostBuilder.setGifs(_:)`. GIFs can sit beside images, videos, files and audio, up to 10 attachments in total. A post with only GIFs has the `gif` structure type; a post that mixes GIFs with other media is `mixed`.
  - **Read:** GIF child posts have the new `AmityPostDataType.gif` data type. Call `AmityPost.getGifInfo()` on a child post to get its `AmityGifData`, and `AmityPost.PostData` gains a `gif(text:data:)` case.
  - **Editing:** the GIF list you pass on edit is the full set to keep, so pass back each kept GIF from `getGifInfo()`. `AmityMixedMediaPostBuilder.removeAllAttachments()` removes every attachment and turns the post into a text post. Edit GIF posts with `AmityMixedMediaPostBuilder`, not `AmityImagePostBuilder`, which would drop the GIFs.

  #### GIF Attachments on Comments

  A comment or reply can now hold one GIF through `AmityCommentAttachment.gif(url:width:height:)`, with the new `AmityCommentDataType.gif` data type.

  - **Create, reply and edit** send the GIF as an attachment. On edit, a new GIF replaces the old one, and an empty attachment list removes it while keeping the text.
  - **Query filters:** the `.any` and `.exact` data type filters accept `.gif`.
  - **Validation:** the URL must use https, end in `.gif`, and be at most 2,000 characters. Its host must be on the network's allow list, or the call fails with `AmityErrorCode.linkNotAllowed` (400309).

<Update label="8.11.0  (16/10/2026)" tags={["New Releases"]}>
  ## 🚀 New Features

  #### Child Endangerment Report Reason

  Added `AmityContentFlagReasonType.childEndangerment`, so users can report posts, comments, messages and user behavior for child endangerment. It is sent as "Child endangerment", which the Console moderation feed can filter on.

  #### Report Reason List from the SDK

  `AmityContentFlagReasonType.allCases` is now the report-reason list in display order, with `.childEndangerment` second and `.others` last. Build your reason picker from it:

  - **`key`:** a stable snake_case identifier, the same on every platform. Use it to look up a translated label.
  - **`defaultLabel`:** the canonical English label, to show when no translation exists.

  New reasons can arrive in minor releases, so add `@unknown default` to any `switch` over `AmityContentFlagReasonType`. The legacy `AmityContentFlagReason` is unchanged and does not get the new reason.

<Update label="8.10.0  (09/10/2026)" tags={["New Releases","Improvements"]}>
  ## 🚀 New Features

  #### Flag Reasons with Optional Detail

  Added `AmityContentFlagReasonType`, a reason category with no attached text, and new flag overloads that take it with an optional `detail`:

  - `flagPost(withId:reason:detail:)`, `flagComment(withId:reason:detail:)` and `flagMessage(withId:reason:detail:)`.
  - `flagPost(withId:)` flags a post without a reason, using `.communityGuidelines`, matching the comment and message calls. `flagMessage(withId:)` is no longer deprecated.
  - The overloads that take the legacy `AmityContentFlagReason` are deprecated. For `.others(text)`, pass `reason: .others, detail: text`.

  #### Separate User Profile and Behavior Reports

  `AmityUserRepository` has two purpose-built user reports:

  - **`flagUserProfile(withId:field:comment:)`** reports a profile field, an `AmityUserProfileField` (`displayName`, `description` or `avatar`).
  - **`flagUserBehavior(withId:reason:comment:)`** reports behavior with an `AmityContentFlagReasonType`.
  - Both trim `comment` and omit it when blank. A comment over 300 characters fails with `invalidParameter` before any request is sent.
  - `flagUser(withId:)` files a report with no type. The four-parameter `flagUser(withId:reportType:reason:comment:)` is deprecated.

  #### Per-Type User Flag Read-Back and Unflag

  - **`AmityUser.isFlaggedByMe`:** whether the current user has reported this user. The observed user updates if the answer changes.
  - **`AmityUser.getUserFlagsByMe()`:** returns an `AmityUserFlagByMe` with the current user's reports on that user, one `AmityUserFlag` (report type, reason, comment, date) per report.
  - **`unflagUser(withId:reportType:)`:** removes one type of report with an `AmityUserReportTypeFilter` (`displayName`, `description`, `avatarFileId`, `behavior` or `untyped`). Leave it `nil` to remove them all.
  - `AmityUserRepository.isUserFlaggedByMe(withId:)` is deprecated in favor of `AmityUser.isFlaggedByMe` and `getUserFlagsByMe()`.

  #### Sort Channels by Last Message

  `AmityChannelQueryOptions` takes a new `sortBy: AmityChannelSortBy`. `.lastActivity` is the default and keeps today's order. `.lastMessage` lists channels by newest message first, and only a new message moves a channel. `AmityChannel.lastMessageAt` exposes the time of the latest message.

  ## ✨ Improvements

  - Added a `searchBy` parameter to `AmityChannelMembership.searchMembers(displayName:searchBy:filterBuilder:roles:includeDeleted:)` to choose which user fields the keyword matches, for example display name only when looking up a user to mention in chat. Left empty, it matches all searchable fields as before.
  - Added `AmityErrorCode.globalMute` (400313), returned when a network-wide mute blocks an action, and `AmityErrorCode.unsafeContent` (400314), returned when a safety check rejects submitted content.

  ## 🐞 Bug Fixes

  - Fixed the "Sexual content or nudity" reason being sent with the wrong value when flagging posts, comments, messages and users.
  - Fixed a fetched community invitation missing its inviter and target community.

<Update label="8.9.0  (29/09/2026)" tags={["New Releases"]}>
  ## 🚀 New Features

  #### Module Settings

  Read which product modules your network is entitled to, so your app can hide features the network does not have.

  - **Read it:** `AmityClient.getModuleSettings()` returns an `AmityModuleSettings`, or `nil` before the first successful fetch. The SDK fetches it after login and keeps the last value if a refresh fails, so it also works offline.
  - **Check a module:** `availability(of:)` takes an `AmityModule`, and `availability(ofKey:)` takes a raw key for modules this SDK version does not know yet. Each returns an `AmityModuleAvailability` with `isAvailable` and `isGranted`, and names any unmet prerequisites.
  - **Enforcement:** `AmityModuleSettings.enforcement` is an `AmityModuleEnforcementMode` (`off`, `shadow`, `enforce`). Under `off`, every module works even when it is not granted.
  - **Updates:** `AmityModuleSettings.didUpdateNotification` is posted on the main thread after each successful fetch.
  - **Refused calls:** when the network lacks a module a call needs, the call fails with `AmityErrorCode.moduleNotEntitled` (400325) as an `AmityModuleNotEntitledError` whose `modules` lists every missing module.

<Update label="8.8.0  (25/09/2026)" tags={["New Releases","Improvements"]}>
  ## 🚀 New Features

  #### Comment Approval for Communities

  A community can now require review before a new comment is visible. While a comment is pending, only its author, the community's reviewers, and network admins can see it. It stays out of public comment lists and comment counts until a reviewer approves it. See [Comment Review](/social-plus-sdk/social/content-management/comments/moderation/comment-review).

  - **Turn it on:** `AmityCommunityDataBuilder.setNeedApprovalOnCommentCreation(_:)` on create or update. Read it back with `AmityCommunity.isCommentReviewEnabled`.
  - **Approval status:** `AmityComment.approvalStatus` is an `AmityCommentApprovalStatus` (`pending`, `approved`, `rejected`).
  - **Create without a local copy:** `AmityCommentCreateOptions(isOptimistic: false)` skips the local comment, so the comment you get back carries the server's approval status. The default, `true`, keeps today's behavior.
  - **Review queue:** `AmityCommentRepository.getCommentReviewQueue(with:)` returns the community's pending comments as an `AmityCollection<AmityComment>`. Narrow it to one post or a date range with `AmityCommentReviewQueueQueryOptions`.
  - **Approve or decline:** `AmityCommentRepository.approveComment(withId:)` and `declineComment(withId:reason:)`. Declining deletes the comment. The optional `reason` (at most 250 characters) is kept for the moderation record only.
  - **Permission:** reviewers need `AmityPermission.reviewCommunityComment`.
  - **Editing while pending:** `AmitySocialSettings.isAllowEditCommentWhenReviewingEnabled` tells you whether an author may edit a pending comment.
  - **Realtime:** an approved comment appears as soon as it is approved, through the `comment.approved` event. A declined comment arrives as a deletion.

  #### Curated Content

  Fetch the posts selected for a topic configured in the Console, and build your own discovery surface around them. A pool is one bounded, ranked result with no pagination, and the SDK keeps the server's order. See [Topic-based Content Discovery](/social-plus-sdk/social/discovery-engagement/feed/curated-content).

  - **Fetch a pool:** `AmityCuratedContentRepository.getPool(topicId:limit:)` is an `async throws` call that returns an `AmityCuratedContentPool`. `limit` must be between 1 and 100.
  - **Analytics:** `AmityCuratedContentTopic.analytics` (`AmityCuratedContentAnalytics`) provides `markAsViewed()`, `markPostAsViewed(postId:)`, and `markPostClick(postId:)`.

  #### Pin Message in Live Channels

  Pin one message in a live channel so it stays visible above the chat. Pinning a new message replaces the current pin. The server clears the pin when the message is deleted or its author is banned from the channel or globally. See [Pin and Unpin Messages](/social-plus-sdk/chat/messaging-features/messages/pin-message).

  - **Pin and unpin:** `AmityMessageRepository.pinMessage(withId:)` and `unpinMessage(withId:)`.
  - **Read the pin:** `AmityChannel.pinnedMessage` holds the current pinned message, or `nil` when nothing is pinned.
  - **Permission:** `AmityPermission.pinMessage`. Channel moderators, and livestream hosts and co-hosts, have it by default. Channel role changes now update a member's permissions in real time, so a promoted or demoted member's pin permission changes immediately.
  - **Realtime:** the observed `AmityChannel` updates on every pin and unpin, driven by the `channel.messagePinned` and `channel.messageUnpinned` events.

  #### Typed Network Activity Observation

  Added `AmityClient.observeNetworkActivities(_:)`, a typed observer that supports multiple observers and replaces the previous single-slot callback. It returns a cancellable `AmityNetworkActivityToken` and delivers `AmityNetworkActivity` records for HTTP, upload, download, and MQTT traffic. Each record is labeled with an `AmityNetworkActivityType` and carries real timings and byte counts. The previous `observeNetworkActivities((URLRequest?, HTTPURLResponse?, Data?) -> Void)` overload is deprecated but still works.

  ## ✨ Improvements

  - Added `AmityPost.getLocalCommentCount(includePending:)`. By default, the count leaves out the current user's own comments that are still awaiting approval. Pass `true` to include them. `AmityPost.localCommentCount` is now deprecated and equals `getLocalCommentCount(includePending: true)`.
