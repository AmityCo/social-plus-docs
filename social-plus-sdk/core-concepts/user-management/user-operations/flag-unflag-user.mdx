---
title: "Flag and Unflag Users"
description: "Flag users with an optional report type, withdraw one report or all of them, and read back which reports you filed, with social.plus SDK."
---

Use user flagging when a member reports another user for moderator review. Flagging does not block, ban, or delete the user; it records reporting state that moderation workflows can review.

A member can hold several reports on the same user, one per report type plus one typeless report. You can send a simple flag (just the `userId`) or a **structured report** that says _what_ is being reported and _why_, withdraw **one** report or all of them, and read back **which** reports the current member has filed so your UI can disable the options already used.

<Info>
  Flutter exposes flag and unflag actions from an `AmityUser` object.
  TypeScript, iOS, and Android expose repository methods that take a `userId`.
</Info>

<Note>
  Per-report-type unflag and the detailed flag-state result ship in the
  October 2026 SDK releases for TypeScript, iOS, and Android. Flutter keeps
  the boolean flag state and the all-at-once unflag.
</Note>

## Parameters

| Operation         | Required inputs                                        | Platforms                         | Result shape                                                                                                                          |
| ----------------- | ------------------------------------------------------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Flag user         | `userId` (optional: `reportType`, `reason`, `comment`) | TypeScript, iOS, Android          | TypeScript returns `Promise<Amity.User>`; iOS async call throws on failure; Android returns `Completable`.                            |
| Flag user         | `AmityUser` object                                     | Flutter                           | Returns `Future<AmityUser>`.                                                                                                          |
| Unflag user       | `userId` (optional: `reportType`)                      | TypeScript, iOS, Android          | TypeScript returns `Promise<boolean>`; iOS async call throws on failure; Android returns `Completable`.                               |
| Unflag user       | `AmityUser` object                                     | Flutter                           | Returns `Future<AmityUser>`. Withdraws all of your reports.                                                                           |
| Check flag status | `userId`                                               | TypeScript, iOS, Android          | A flag-state result: `isFlagByMe` plus the list of your own reports (`flags`). TypeScript `Promise<Amity.UserFlagByMe>`, iOS `AmityUserFlagByMe` from `AmityUser.getUserFlagsByMe()`, Android `Single<AmityUserFlagByMe>`. |
| Check flag status | `AmityUser` object                                     | Android, Flutter                  | Boolean flag state from the loaded user model.                                                                                        |

## Flag a user

Call the flag API when the current user reports another user.

### Inputs

| Platform   | Method                                                            | Required inputs                                       | Result shape                                      |
| ---------- | ----------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------- |
| Android    | `userRepository.flagUser(userId, reportType?, reason?, comment?)` | `userId` (optional `reportType`, `reason`, `comment`) | Returns `Completable`.                            |
| iOS        | `userRepository.flagUser(withId:reportType:reason:comment:)`      | `userId` (optional `reportType`, `reason`, `comment`) | Async call that throws on failure.                |
| TypeScript | `UserRepository.flagUser(userId, options?)`                       | `userId` (optional `reportType`, `reason`, `comment`) | Returns `Promise<Amity.User>` — the flagged user. |
| Flutter    | `user.report().flag()`                                            | `AmityUser` object                                    | Returns `Future<AmityUser>`.                      |

<CodeGroup>
```kotlin Android
fun flagUser(userRepository: AmityUserRepository, userId: String) {
    userRepository.flagUser(userId = userId)
        .doOnComplete {
            Log.d("UserFlag", "User flagged")
        }
        .doOnError { error ->
            Log.e("UserFlag", "Flag failed", error)
        }
        .subscribe()
}
```

```swift iOS
func flagUser() async {
    do {
        try await userRepository.flagUser(withId: "<user-id>")
        print("User flagged")
    } catch {
        print("Flag failed: \(error)")
    }
}
```

```typescript TypeScript
import { UserRepository } from '@amityco/ts-sdk';

async function flagUser(userId: string) {
  const flagged = await UserRepository.flagUser(userId);
  console.log('Flagged:', flagged);
}
```

```dart Flutter
Future<void> flagUser(AmityUser user) async {
  try {
    final updatedUser = await user.report().flag();
    print('Flagged user: ${updatedUser.userId}');
  } on AmityException catch (error) {
    print('Flag failed: ${error.message}');
  }
}
```
</CodeGroup>

## Add a report type, reason, and comment (optional)

When you want moderators to know _what_ part of a profile is being reported and _why_, attach one or more optional fields to the flag call.

| Field        | Answers    | Description                                                                                                                                            |
| ------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `reportType` | **What**   | The aspect of the profile being reported. One of `displayName`, `description`, `avatarFileId`, or `behavior`. Omit it for a generic (typeless) report. |
| `reason`     | **Why**    | A predefined reason for a `behavior` report. **Required** when `reportType` is `behavior`, and not allowed with any other type.                        |
| `comment`    | **Detail** | Free-text context from the reporter (max 300 characters). Allowed with any report type, including a typeless report.                                   |

### Report types

`reportType` uses fixed values; your app decides the label to show the member.

| Value          | Suggested label | Reports the user's…           |
| -------------- | --------------- | ----------------------------- |
| `displayName`  | Username        | display name                  |
| `description`  | Bio             | bio / description             |
| `avatarFileId` | Avatar          | profile image                 |
| `behavior`     | Behavior        | conduct (requires a `reason`) |

### Reasons

For a `behavior` report, pass a `reason` from the shared content report-reason list (the same values used when flagging posts, comments, and messages): `communityGuidelines`, `harassmentOrBullying`, `selfHarmOrSuicide`, `violenceOrThreateningContent`, `sellingRestrictedItems`, `sexualContentOrNudity`, `spamOrScams`, `falseInformation`, or `others` with a custom string.

### Rules

<Info>
  - `reason` is **required** when `reportType` is `behavior`, and **rejected** for every other type (and for typeless reports).
  - `reason` and `comment` are each capped at **300 characters**.
  - A member holds **one report per report type** on a target (up to four typed reports plus one typeless). Reporting the **same** type again updates that report; reporting a **different** type adds a new one.
  - Unflagging without a `reportType` removes **all** of your reports on that user. Pass a `reportType` to withdraw just one — see [Unflag a user](#unflag-a-user).
  - Breaking a rule returns a validation error (HTTP `422`) from the server.
</Info>

### Examples

Pass the optional fields alongside the `userId`. Send `reason` only with a `behavior` report, and add a `comment` on any report type when the reporter provides extra detail.

<CodeGroup>
```kotlin Android
// Report a user's behavior, with a reason and comment
userRepository.flagUser(
    userId = userId,
    reportType = AmityUserReportType.BEHAVIOR,
    reason = AmityContentFlagReason.SpamOrScams,
    comment = "Repeatedly posting promo links"
).subscribe()

// Report a profile field (no reason)
userRepository.flagUser(
    userId = userId,
    reportType = AmityUserReportType.AVATAR
).subscribe()
```

```swift iOS
// Report a user's behavior, with a reason and comment
try await userRepository.flagUser(
    withId: "<user-id>",
    reportType: .behavior,
    reason: .spamOrScams,
    comment: "Repeatedly posting promo links"
)

// Report a profile field (no reason)
try await userRepository.flagUser(withId: "<user-id>", reportType: .avatarFileId)
```

```typescript TypeScript
import { ContentFlagReasonEnum, UserReportTypeEnum, UserRepository } from '@amityco/ts-sdk';

// Report a user's behavior, with a reason and comment
await UserRepository.flagUser(userId, {
  reportType: UserReportTypeEnum.BEHAVIOR,
  reason: ContentFlagReasonEnum.SpamOrScams,
  comment: 'Repeatedly posting promo links',
});

// Report a profile field (no reason)
await UserRepository.flagUser(userId, { reportType: UserReportTypeEnum.AVATAR });
```
</CodeGroup>

<Tip>
  To report more than one aspect of the same profile (for example the avatar
  **and** the behavior), send a separate flag call for each `reportType`. They
  are stored as distinct reports.
</Tip>

## Unflag a user

Call the unflag API when the current user withdraws a report from another user. Without a `reportType` it withdraws every report you filed on that user. With a `reportType` it withdraws only that one and leaves your other reports in place.

### Inputs

| Platform   | Method                                           | Required inputs                       | Result shape                       |
| ---------- | ------------------------------------------------ | ------------------------------------- | ---------------------------------- |
| Android    | `userRepository.unflagUser(userId, reportType?)` | `userId` (optional `reportType`)      | Returns `Completable`.             |
| iOS        | `userRepository.unflagUser(withId:reportType:)`  | `userId` (optional `reportType`)      | Async call that throws on failure. |
| TypeScript | `UserRepository.unflagUser(userId, options?)`    | `userId` (optional `reportType`)      | Returns `Promise<boolean>`.        |
| Flutter    | `user.report().unflag()`                         | `AmityUser` object                    | Returns `Future<AmityUser>`. Withdraws all of your reports. |

### Which report is withdrawn

| `reportType`                                               | Withdraws                                       |
| ---------------------------------------------------------- | ----------------------------------------------- |
| omitted                                                    | every report you filed on that user             |
| `displayName`, `description`, `avatarFileId`, `behavior`   | only your report of that type                   |
| `untyped`                                                  | only your typeless report (the one filed without a `reportType`) |

`untyped` exists only for unflag. It names the typeless report, which the flag API never accepts as a type and which the flag-state result returns as `reportType: null`.

<Info>
  - Withdrawing a report you never filed succeeds and changes nothing, so withdrawing twice is safe.
  - Other members' reports on the same user are never affected, even of the same type.
  - After a per-type unflag you may still hold other reports on that user. Do not set a local "flagged by me" value to `false` after an unflag; read the flag state again instead.
</Info>

<CodeGroup>
```kotlin Android
fun unflagUser(userRepository: AmityUserRepository, userId: String) {
    // Withdraw every report you filed on this user
    userRepository.unflagUser(userId = userId)
        .doOnComplete {
            Log.d("UserFlag", "User unflagged")
        }
        .doOnError { error ->
            Log.e("UserFlag", "Unflag failed", error)
        }
        .subscribe()
}

fun withdrawBehaviorReport(userRepository: AmityUserRepository, userId: String) {
    // Withdraw only your behavior report; your other reports stay
    userRepository.unflagUser(
        userId = userId,
        reportType = AmityUserReportTypeFilter.BEHAVIOR
    ).subscribe()
}

fun withdrawTypelessReport(userRepository: AmityUserRepository, userId: String) {
    userRepository.unflagUser(
        userId = userId,
        reportType = AmityUserReportTypeFilter.UNTYPED
    ).subscribe()
}
```

```swift iOS
func unflagUser() async {
    do {
        // Withdraw every report you filed on this user
        try await userRepository.unflagUser(withId: "<user-id>")
        print("User unflagged")
    } catch {
        print("Unflag failed: \(error)")
    }
}

func withdrawBehaviorReport() async throws {
    // Withdraw only your behavior report; your other reports stay
    try await userRepository.unflagUser(withId: "<user-id>", reportType: .behavior)
}

func withdrawTypelessReport() async throws {
    try await userRepository.unflagUser(withId: "<user-id>", reportType: .untyped)
}
```

## Check which reports you filed on a user

Use the flag-state API to decide what to show: a "reported" badge, which report options to disable because the current member already used them, and a withdraw action per report. Only the current member's own reports come back; other members' reports are never exposed.

<Warning>
  On TypeScript this call previously returned a boolean. From the October 2026
  releases it returns a flag-state result. Read `isFlagByMe` on the result for
  the same yes/no answer.

  On iOS nothing breaks: `userRepository.isUserFlaggedByMe(withId:)` still
  returns a boolean and is now **deprecated**. Use `AmityUser.isFlaggedByMe` and
  `AmityUser.getUserFlagsByMe()` instead.
</Warning>

### Inputs

| Platform   | Method                                        | Required inputs    | Result shape                                                    |
| ---------- | --------------------------------------------- | ------------------ | --------------------------------------------------------------- |
| Android    | `userRepository.isUserFlaggedByMe(userId)`    | `userId`           | Returns `Single<AmityUserFlagByMe>`.                            |
| Android    | `user.isFlaggedByMe()`                        | `AmityUser` object | Returns `Boolean` from the loaded user model (yes/no only).     |
| iOS        | `user.isFlaggedByMe`                          | `AmityUser` object | Returns `Bool`, a quick hint with no request (see below).       |
| iOS        | `user.getUserFlagsByMe()`                     | `AmityUser` object | Returns `AmityUserFlagByMe` from an async call.                 |
| iOS        | `userRepository.isUserFlaggedByMe(withId:)`   | `userId`           | **Deprecated.** Returns `Bool` from an async call.              |
| TypeScript | `UserRepository.isUserFlaggedByMe(userId)`    | `userId`           | Returns `Promise<Amity.UserFlagByMe>`.                          |
| Flutter    | `user.isFlaggedByMe`                          | `AmityUser` object | Returns `bool` from the loaded user model (yes/no only).        |

### Result

| Field                | Type                                                              | Description                                                                                         |
| -------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `isFlagByMe`         | boolean                                                           | `true` when the current member holds any report on the user.                                        |
| `flags`              | list                                                              | The current member's own reports on the user, in server order. Empty when not reported.             |
| `flags[].reportType` | `displayName`, `description`, `avatarFileId`, `behavior`, or null | Which aspect was reported. `null` is the typeless report; withdraw it with `untyped`.               |
| `flags[].reason`     | string or null                                                    | The stored reason. Present on `behavior` reports.                                                   |
| `flags[].comment`    | string or null                                                    | The stored reporter comment.                                                                        |
| `flags[].createdAt`  | date-time or null                                                 | When the report was filed. `null` for reports filed before report types existed.                    |

Every field is always present; a field the report does not carry is `null`. The result is read from the server on each call and is not cached.

<CodeGroup>
```kotlin Android
fun checkFlagState(userRepository: AmityUserRepository, userId: String) {
    userRepository.isUserFlaggedByMe(userId = userId)
        .doOnSuccess { result ->
            Log.d("UserFlag", "Flagged by me: ${result.isFlagByMe}")

            // Disable the report options the member already used
            val usedTypes = result.flags.map { it.reportType }.toSet()
            val canReportBio = AmityUserReportType.DESCRIPTION !in usedTypes
            Log.d("UserFlag", "Can report bio: $canReportBio")
        }
        .doOnError { error ->
            Log.e("UserFlag", "Flag-state check failed", error)
        }
        .subscribe()
}
```

```swift iOS
func checkFlagState(user: AmityUser) async {
    // A quick hint with no request: false is exact, true can be a false positive
    print("Probably flagged by me: \(user.isFlaggedByMe)")

    do {
        // The exact reports; skips the request when the hint is false
        let result = try await user.getUserFlagsByMe()
        print("Flagged by me: \(result.isFlagByMe)")

        // Disable the report options the member already used
        let usedTypes = Set(result.flags.map { $0.reportType })
        let canReportBio = !usedTypes.contains(.description)
        print("Can report bio: \(canReportBio)")
    } catch {
        print("Flag-state check failed: \(error)")
    }
}
```

```typescript TypeScript
import { UserReportTypeEnum, UserRepository } from '@amityco/ts-sdk';

async function checkFlagState(userId: string) {
  const { isFlagByMe, flags } = await UserRepository.isUserFlaggedByMe(userId);
  console.log('Flagged by me:', isFlagByMe);

  // Disable the report options the member already used; null marks the typeless report
  const usedTypes = new Set(flags.map(flag => flag.reportType));
  const canReportBio = !usedTypes.has(UserReportTypeEnum.DESCRIPTION);
  console.log('Can report bio:', canReportBio);
}
```

```dart Flutter
void checkFlagState(AmityUser user) {
  final isFlaggedByMe = user.isFlaggedByMe;
  print('Flagged by me: $isFlaggedByMe');
}
```
</CodeGroup>

### Withdraw one of the listed reports

Each entry in `flags` maps to one unflag call. Pass its `reportType`, or `untyped` when the entry's `reportType` is `null`.

<Warning>
  On Android and iOS the `reportType` parameter of unflag is optional, and
  omitting it (or passing `nil`) withdraws **all** of your reports. An entry
  whose `reportType` is `null` is the typeless report: pass `untyped`, not `nil`.
</Warning>

<CodeGroup>
```kotlin Android
fun withdrawAllListedReports(userRepository: AmityUserRepository, userId: String) {
    userRepository.isUserFlaggedByMe(userId = userId)
        .flatMapCompletable { result ->
            Completable.concat(
                result.flags.map { flag ->
                    val filter = when (flag.reportType) {
                        AmityUserReportType.DISPLAY_NAME -> AmityUserReportTypeFilter.DISPLAY_NAME
                        AmityUserReportType.DESCRIPTION -> AmityUserReportTypeFilter.DESCRIPTION
                        AmityUserReportType.AVATAR -> AmityUserReportTypeFilter.AVATAR
                        AmityUserReportType.BEHAVIOR -> AmityUserReportTypeFilter.BEHAVIOR
                        null -> AmityUserReportTypeFilter.UNTYPED
                    }
                    userRepository.unflagUser(userId = userId, reportType = filter)
                }
            )
        }
        .subscribe()
}
```

```swift iOS
func withdrawAllListedReports(user: AmityUser) async throws {
    let result = try await user.getUserFlagsByMe()
    for flag in result.flags {
        let filter: AmityUserReportTypeFilter
        switch flag.reportType {
        case .displayName: filter = .displayName
        case .description: filter = .description
        case .avatarFileId: filter = .avatarFileId
        case .behavior: filter = .behavior
        case .none: filter = .untyped
        @unknown default: filter = .untyped
        }
        try await userRepository.unflagUser(withId: user.userId, reportType: filter)
    }
}
```

```typescript TypeScript
import { UserReportTypeFilterEnum, UserRepository } from '@amityco/ts-sdk';

async function withdrawAllListedReports(userId: string) {
  const { flags } = await UserRepository.isUserFlaggedByMe(userId);
  for (const flag of flags) {
    // A null reportType is the typeless report; unflag selects it with 'untyped'
    const reportType = flag.reportType ?? UserReportTypeFilterEnum.UNTYPED;
    await UserRepository.unflagUser(userId, { reportType });
  }
}
```
</CodeGroup>

## Platform notes

- Flagging is a report signal for moderation review; it does not automatically block, ban, or delete the user.
- TypeScript, iOS, and Android flag, unflag, and read flag state by `userId`.
- Flutter flags and unflags through the loaded `AmityUser` object, withdraws all reports at once, and exposes a boolean flag state only.
- Android also keeps the boolean `isFlaggedByMe()` on the loaded user model; use the repository call when you need the per-report list.
- On iOS, `AmityUser.isFlaggedByMe` is read from the user's `hashFlag` bloom filter when the user is loaded, so it needs no request. `false` is exact; `true` can be a false positive, and it only reflects the user as of its last update. Use it to draw a feed row or a badge, and call `getUserFlagsByMe()` when you show the options to flag or unflag. `getUserFlagsByMe()` skips the request when `isFlaggedByMe` is `false`.
- The backend returns the updated user, including its current `flagCount`, and the SDK saves it. Read flag state after a flag or unflag when your UI needs the updated per-report list.
