Use `AmityFeedRepository` to read feed-style post collections. Every feed is a live collection: it emits an initial page, pages forward on demand, and keeps emitting as posts change.

## Which feed do I use?

<CardGroup cols={2}>
  <Card title="Global Feed" icon="globe" href="./global-feed">
    Network-wide posts, either chronological or ranked by engagement. The default "what's happening" surface.
  </Card>
  <Card title="For You Feed" icon="sparkles" href="./for-you-feed">
    Backend-personalized per user, mixing joined and public communities, followed users, and live streams.
  </Card>
  <Card title="User & Community Feed" icon="user" href="./user-and-community-feed">
    One user's timeline or one community's posts, with privacy rules and time-bounded pagination.
  </Card>
  <Card title="Query Posts" icon="newspaper" href="/social-plus-sdk/social/content-management/posts/retrieval/query-posts">
    Richer filters — tags, review status, deletion state — when a feed API is too coarse.
  </Card>
</CardGroup>

| If you need… | Use |
| --- | --- |
| A chronological network-wide feed | [Global feed](./global-feed) |
| A network-wide feed ordered by engagement | [Custom-ranking global feed](./global-feed#custom-ranking-global-feed) |
| A per-user personalized feed | [For You feed](./for-you-feed) |
| One user's posts, including their public-community posts | [User feed](./user-and-community-feed) |
| One community's posts | [Community feed](./user-and-community-feed#community-feed) |
| Posts filtered by tag, review status, or deletion state | [Query posts](/social-plus-sdk/social/content-management/posts/retrieval/query-posts) |

</Note>

## Working with feed live collections

These apply to every feed API on this page.

<AccordionGroup>
  <Accordion title="Pagination" icon="list">
    TypeScript feeds page through `onNextPage` / `hasNextPage` on the callback payload. iOS uses `nextPage()` on the collection. Android returns `PagingData` and pages through the Paging library. Default page size is 20.
  </Accordion>

  <Accordion title="Disposal" icon="trash">
    Dispose live collection subscriptions, notification tokens, and stream subscriptions when the screen is destroyed. In TypeScript call the returned unsubscriber; on iOS invalidate the `AmityNotificationToken`; on Android dispose the RxJava subscription.
  </Accordion>

  <Accordion title="Android cache invalidation" icon="rotate">
    Android feed builders expose `invalidateCache(true)` for deliberate refresh flows, such as pull-to-refresh, when the first page should not reuse the existing paging cache.

    ```kotlin Android
    AmitySocialClient.newFeedRepository()
        .getGlobalFeed()
        .invalidateCache(invalidateCache = true)
        .build()
        .query()
        .subscribe(
            { pagingData: PagingData<AmityPost> -> showSuccessMessage(pagingData) },
            { error -> handleGeneralError(error) }
        )
    ```
  </Accordion>
</AccordionGroup>

<Note>
Ranking behavior is backend-owned for both the custom-ranking global feed and the For You feed. The SDK selects which feed endpoint to query; it does not expose ranking weights or formulas. Do not hardcode ranking assumptions in client UI logic.
</Note>
