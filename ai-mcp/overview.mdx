## Which one do you need?

| You want to… | Use |
|---|---|
| Ask "which communities grew fastest this month?" and get an answer with data | [Agentry](/ai-mcp/agentry/overview) |
| Let Claude, Cursor, or Copilot read the SDK docs while you code | [Documentation MCP Server](/ai-mcp/docs-mcp-server) |
| Have an AI agent build a social.plus feature end to end, with checks | [Vise](/ai-mcp/vise/overview) |

They compose: a team might build its app with Vise, keep the docs MCP server connected in every editor, and give marketing and community managers Agentry for the questions that used to become dashboard requests.

## The shape of AI-native social.plus

- **Your data answers back.** Agentry turns the engagement data your app already generates — posts, comments, reactions, members, communities — into a conversation. Read-only, scoped to one community, authorized by your admins.
- **The docs meet your tools where they are.** The documentation MCP server is a public, no-auth endpoint any MCP-capable tool can read, so assistants cite canonical guidance instead of guessing.
- **Building is verifiable.** Vise gives coding agents the project knowledge and verification steps to implement features that pass review, not just compile.
