## For You Feed

As a community grows, the posts worth a member's attention get buried by volume. The **For You** tab surfaces the posts each member is most likely to care about, so the home experience stays relevant and worth returning to — without you building any ranking logic yourself.

For You is a backend-personalized feed that appears as a tab on the social home page. It is a **network-level setting** — the tab only shows when the network has For You feed enabled and the current user is not a visitor or bot. When the setting is off (or the feed reports that it is disabled), the UIKit hides the tab and falls back to the newsfeed automatically.

<Info>
**Platform Support**: For You feed is available on the **React Web, iOS, and Android** UIKit. It is not available on Flutter or React Native.
</Info>

### What the For You feed includes

The backend assembles For You from these content sources, then ranks them for the current user:

| Source | What it contributes |
| --- | --- |
| Joined communities | Posts from communities the user is a member of |
| Public communities | Posts from public communities the user has **not** joined |
| Followed users | Posts from the user feeds the user follows |
| Public user feeds | Posts from user feeds that are public |
| Exploration | A small amount of random posts, for controlled discovery |
| Livestreams | Ongoing livestreams, injected while they are live |

<Note>
Ranking, and the mix between these sources, is owned by the backend. There are no client-side knobs in the UIKit or SDK to weight or filter them. For network-level tuning, contact [social.plus Support](https://ekoapp.atlassian.net/servicedesk/customer/portal/3).
</Note>

### How ranking works

The backend ranks each post for the current user by blending four signals — **relevance** (what the user has engaged with before), **affinity** (authors and communities they're connected to), **popularity** (engagement across the network), and **freshness** (how recently it was posted) — then spaces out repetitive authors, communities, and topics so the feed stays varied. New users start with a popularity- and freshness-led feed that personalizes as they engage. The UIKit renders the ranked result as-is; the exact scoring model is backend-owned and not exposed. See [How ranking works](/social-plus-sdk/social/discovery-engagement/feed/for-you-feed#how-ranking-works) for the full behavior.

The UIKit also reports post views for you, so the feed automatically skips posts the member has already seen — on any surface — without extra wiring.

<Info>
**Transparency.** For You is a personalized recommender. Where recommender-system transparency rules apply (such as the EU Digital Services Act), disclose the four signals above to your users in plain language and offer the non-personalized **Newsfeed** as the alternative they can switch to at any time — the tab switch is that control.
</Info>

### How the tab is gated

The social home page reads the network setting and the feed collection, then derives whether to show the For You tab:

1. `useForYouFeedSetting()` reads `forYouFeed.enabled` for the network (skipped for visitors/bots).
2. `useForYouFeedCollection()` observes the personalized posts once the setting is enabled.
3. The tab is shown only when the setting is enabled **and** the collection did not fail with a feed-disabled error. If the feed becomes unavailable while the tab is active, the page switches back to the newsfeed.

### Render the feed

`AmitySocialHomePage` wires the For You tab for you — enable For You feed on your network and it appears automatically. To embed the feed on its own, render the `ForYouFeed` component with a `pageId`:

### Hooks

| Hook | Returns | Use for |
| --- | --- | --- |
| `useForYouFeedSetting({ shouldCall })` | `{ forYouFeedSetting, isPending, error }` | Decide whether to render a For You entry point. Pass `shouldCall: !isVisitorOrBot`. |
| `useForYouFeedCollection({ shouldCall })` | `{ posts, isLoading, hasMore, loadMore, error, refresh, isLoadingFirstPage }` | Render the personalized post list and paginate it. Gate `shouldCall` on the enabled setting. |

<Note>

</Note>

## Video Autoplay

Members scroll past a still thumbnail without knowing what the video holds. With **Video Autoplay**, a feed video starts playing, muted, as soon as the member scrolls to it. Members see the content at once, and they can turn the sound on with one tap.

Video Autoplay is a **network-level setting**, and it is off by default. When you turn it on, the UIKit plays feed videos for you. You do not add any code to the feeds.

<Info>
**Platform Support**: Video Autoplay is available on the **React Web, iOS, and Android** UIKit. It is not available on Flutter or React Native. Those UIKits keep the thumbnail and play button.
</Info>

### Turn autoplay on for your network

Set `post.video.autoPlay` with the feed setting API. The call needs an **Admin API Access Token**. The console has no switch for this setting.

```bash
curl -X PUT "https://apix.<region>.amity.co/api/v3/network-settings/feed-setting" \
  -H "Authorization: Bearer <admin-access-token>" \
  -H "Content-Type: application/json" \
  -d '{ "post": { "video": { "autoPlay": true } } }'
```

Send `false` to turn it off again. The call changes only this field and keeps your other feed settings.

<Note>
The UIKit reads the setting each time the SDK session is established: at login, when the app starts, and after a reconnect. It does not read the setting when the app returns from the background. A change reaches each member at their next login, app start or reconnect. If the UIKit cannot read the setting, autoplay stays off until the next successful read.
</Note>

### How playback behaves

| Behavior | What the member sees |
| --- | --- |
| When a video starts | The video starts when half or more of it is on screen. A video taller than the screen starts when it fills half the screen. |
| One at a time | Only one video plays. It keeps playing until less than half of it is on screen. Then the most visible video starts. |
| Sound | Every video starts muted. The sound button on the video turns the sound on for the rest of the session. Logout, an app restart, a web page reload or a new browser tab starts muted again. |
| Other apps' audio | A muted video does not stop music or other audio from another app. The video takes the audio only after the member turns the sound on. |
| End of a video | The video plays once. It stops on a dimmed last frame with a **Watch again** button. It does not loop and does not move to the next video. |
| Scrolling back | The video continues from the point where it stopped. Post detail and the full-screen player continue from the same point. |
| Loading | A spinner shows over the video if it takes more than 1 second to start, or at once if it stops to load while it plays. |
| Covered or left | The video pauses when a sheet, a menu, the full-screen player or another page covers the feed, or when the app goes to the background. It continues when the member returns. |
| Carousels | Swiping to a video page plays it. The page the member swiped away from pauses. |
| Livestream posts | Live and recorded livestream posts follow the same rules. A preview in the feed does not count as a view and does not add the member to the viewer list. |

<Note>
To make room for the sound button, the product tag badge on feed media now sits at the **bottom-left**. In the post composer, the ALT badge moves to the bottom-right.
</Note>

### Where videos autoplay

Videos autoplay in these places:

- The global feed, the For You feed, community feeds, event discussion feeds and user feeds, including the pinned and announcement posts at the top
- The **Pin** tab of a community profile
- Post detail

These places keep the thumbnail and play button:

- Search results
- Pending posts
- The **Videos** and **Livestream** tabs of a community profile
- The media gallery

### When videos do not autoplay

The feed shows the thumbnail and play button, and nothing plays, when any of these is true:

- The network setting is off, or the UIKit could not read it.
- The member chose **Never**, or chose **on Wi-Fi only** while on mobile data.
- **Low Data Mode** (iOS) or **Data Saver** (Android) is on.
- The browser blocks autoplay (React Web).
- The device is offline.

If one of these becomes true while a video plays, the video stops at once and keeps its position. If a video fails to play, the frame also shows the thumbnail and play button. A tap opens the full-screen player in every case.

### Member setting

Members choose when videos autoplay on their own device. They open their own profile, tap the **⋯** menu, and tap **Autoplay in feed** under **Settings**.

| Platform | Options | Default |
| --- | --- | --- |
| iOS, Android | **on Wi-Fi and mobile data**, **on Wi-Fi only**, **Never** | on Wi-Fi and mobile data |
| React Web | One **Autoplay in feed** switch, **On** or **Off**, on its own page | On |

The choice is saved on the device or in the browser, not on the server. It applies to every user who logs in on that device. When the network setting is off, nothing autoplays, whatever the member chose.

### Read the setting in your own UI

If you build your own feed UI, read the network setting from the SDK. The field is `false` when the server does not send it.

<CodeGroup>
```typescript TypeScript
import { Client } from '@amityco/ts-sdk';

const feedSettings = await Client.getFeedSettings();
const isAutoPlayEnabled =
  feedSettings.post?.find(({ contentType }) => contentType === 'video')?.autoPlay ?? false;
```

```swift iOS
let settings = try await client.getContentSettings()
let isAutoPlayEnabled = settings.post?.videoSettings?.autoPlay ?? false
```

```kotlin Android
AmityCoreClient.getContentCheck()
    .map { it.post()?.video?.autoPlay ?: false }
    .subscribe { isAutoPlayEnabled ->
        // Show or hide autoplay in your feed
    }
```
</CodeGroup>

## Best practices

<AccordionGroup>
  <Accordion title="Social home architecture" icon="home">
    Plan the layout by combining feed components, content creation tools, and community discovery. Consider the user flow from content consumption to creation and community engagement, and where the For You tab sits relative to the newsfeed.
  </Accordion>

  <Accordion title="Balancing consumption and creation" icon="flow">
    Position the create post menu so it encourages user-generated content without competing with content discovery. Community categories, recommendations, and trending displays give users several routes into communities.
  </Accordion>

  <Accordion title="User experience" icon="user-check">
    Keep a clear visual hierarchy between content types, smooth transitions between components, and consistent navigation across social features. Design mobile-first.
  </Accordion>

  <Accordion title="Performance" icon="gauge">
    The SDK handles data fetching and pagination, so focus on UI responsiveness: efficient list rendering, optimized media display, and stable scroll positions when new pages load.
  </Accordion>

  <Accordion title="Customization" icon="palette">
    Match themes, colors, and component behavior to your design system. Adjust styling per context — creation surfaces and consumption surfaces deserve different emphasis.
  </Accordion>
</AccordionGroup>
